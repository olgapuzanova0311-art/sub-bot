# sub-bot — уведомления о подписках/отписках в Telegram

Бот сидит админом в канале или группе, ловит момент, когда кто-то подписался/вступил
или отписался/вышел, и присылает карточку с его именем, ником, ID и ссылкой на
профиль в отдельный чат — в том же формате, что на скриншоте.

Работает без сторонних библиотек, только встроенный Node.js (18+).

## Как это работает

- Бот должен быть **админом** в канале/группе, за которой следим (без этого Telegram
  не присылает события о входах/выходах).
- Уведомления уходят в отдельный чат — `TARGET_CHAT_ID`. Это может быть личка с ботом,
  рабочая группа, что угодно — главное, чтобы бот там тоже состоял.
- Бот поднимает HTTP-сервер и регистрирует webhook в Telegram сам, при старте.

## Переменные окружения

| Переменная | Обязательна | Что это |
|---|---|---|
| `BOT_TOKEN` | да | токен бота от @BotFather |
| `TARGET_CHAT_ID` | нет, но без неё некуда слать | ID чата для уведомлений |
| `PORT` | нет | порт сервера, Railway подставит сам |

## Как узнать TARGET_CHAT_ID

1. Добавь бота в чат, куда должны падать уведомления.
2. Напиши там `/id`.
3. Бот ответит ID этого чата — впиши его в переменную `TARGET_CHAT_ID` и перезапусти сервис.

Если бот не отвечает на `/id` в группе — зайди к @BotFather, `/mybots` → выбери бота →
Bot Settings → Group Privacy → Turn off. Так бот сможет видеть команды в группах.

## Деплой на Railway

1. Создать новый проект на Railway, задеплоить этот код (из GitHub-репозитория или
   через `railway up` из этой папки).
2. Settings → Variables — добавить `BOT_TOKEN` и (по желанию сразу) `TARGET_CHAT_ID`.
3. Settings → Networking → Generate Domain — это даст сервису публичный адрес
   (переменная `RAILWAY_PUBLIC_DOMAIN` подставится автоматически).
4. Передеплой/рестарт после генерации домена — бот сам зарегистрирует webhook
   при старте и это будет видно в логах: `Webhook зарегистрирован: https://...`.

## Локальный запуск (для проверки)

```bash
BOT_TOKEN=твой_токен TARGET_CHAT_ID=твой_chat_id node index.js
```

Без публичного домена webhook не зарегистрируется автоматически — это нормально
для локальной проверки, просто увидишь предупреждение в логах.

## Дальше — MAX

Когда Telegram-часть обкатана, можно добавить второй бот для MAX по такой же схеме:
там для событий вступления/выхода из группы есть события `user_added` и `user_removed`
в вебхуке (`POST /subscriptions` в MAX Bot API). Понадобится токен бота в MAX и
доступ к группе.
